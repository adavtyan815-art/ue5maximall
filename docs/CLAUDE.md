## 4. Protected Invariants & Rules (DO NOT BREAK THESE RULES)

1. **Decoupled Build Targets**:
   - Never commit active `Source/*.Target.cs` files to Git. They are machine-specific and generated by `setup_ue53.bat` (PC1) / `setup_ue56.bat` (PC2).
   - Proven Target profiles are stored under `Build/Targets/PC1_UE53/` and `Build/Targets/PC2_UE56/`.
2. **Canonical Shared C++ Source**:
   - `Source/awsTutorial/` is the single shared functional C++ implementation. Do not create alternate module names or duplicate C++ trees.
3. **Binary Asset Single-Writer Rule**:
   - Binary Unreal assets (`.uasset`, `.umap`) cannot be merged by Git text merge tools. Coordinate ownership before modifying shared Blueprints or the main level (`/Game/MaxiMall.umap`).
4. **Zero Silent Modification Rule**:
   - Never silently modify `Config/DefaultEngine.ini`, `Config/DefaultGame.ini`, or build profiles without reporting and validating on the engine.
5. **No BIM or ShowroomBoothAll Remnants**:
   - The project uses the unified `AShowroomBooth` class. Do not reintroduce superseded experimental classes.

## 5. Change Verification Workflow

Before modifying any file:
1. Inspect the corresponding C++ class in `Source/awsTutorial/` and read [`docs/AWSTUTORIAL_GUIDE.md`](AWSTUTORIAL_GUIDE.md).
2. Ensure proposed changes maintain compatibility across both UE 5.3 (PC1) and UE 5.6 (PC2).

After making changes:
1. Compile Editor C++ (Must succeed with exit code 0).
2. Run `CompileAllBlueprintsCommandlet` (Must report 0 errors, 0 warnings).
3. Test level load for `/Game/MaxiMall` (Must exit cleanly with code 0).
